# 摘要开头与内容分层方法

用于本技能的 HTML 智能总结。用户明确要求开头用多宫格展示各个卖点的重要总结，同时保持清新简约。下面的方法结合参考资料与用户偏好形成，并非某一来源要求的固定模板。用整齐的分组、简短的文字和轻重差异避免杂乱，信息量少时相应缩减，不凑条数。

## 借鉴依据

- [Notion 官方会议笔记指南](https://www.notion.com/help/guides/preserve-perfect-meeting-memory-with-ai-meeting-notes)：区分摘要、原始记录与后续行动，按会议类型组织内容。借鉴“先读整理后的信息，再追溯详细记录”，不照搬产品界面或交互。
- [Atlassian 会议笔记模板](https://www.atlassian.com/dam/jcr%3A60ac65dd-1a22-4f2c-b62f-66cc33906ff9/Meeting%20Notes.pdf)：将讨论、行动和决定分开记录。借鉴信息分类，不把会前议程模板直接当成录音总结。
- [NN/g 关于分层扫读的研究](https://www.nngroup.com/articles/layer-cake-pattern-scanning/)：含义明确、视觉层级一致的小标题帮助读者定位内容；用间距和邻近关系表达分组。借鉴标题与正文的对应关系，避免用过大的标题和不一致的分组制造干扰。

资料查阅于 2026-11-25。来源用于设计参考，不应当混入录音主题的证据来源；只有用户询问设计依据时才在交付说明中提及。

## 开头的默认顺序

1. **主题标题**：直接说明主题，一个标题即可。不额外制作品牌栏、口号、宣传式副标题、插画或右侧导语。
2. **必要元信息**：在标题附近用一行较轻的文字列出生成日期、资料类型或录音时长等确实可得的信息，不为缺失字段造值。完整来源说明放页末。
3. **重点总结多宫格**：每格承载一个卖点或核心要点。最重要的结论放左上首格，其余按重要程度从左到右、从上到下排列，DOM 顺序与视觉顺序一致。不在宫格上方再重复一大块结论。
4. **每格内容**：用一个具体结论式短标题，加一两句通俗解释，说明价值、动作或条件。标题通常约 8–18 个中文字、说明约 30–65 字，按内容自然调整，不截断。保留必要归属和限制；讨论者观点不写成客观定论，产品优势不凭空推导。非产品录音按知识点、观点、决定或行动方向分格，不强行营销化。
5. **正文入口**：摘要结束后再放目录或详细章节。较长文档可用原生 `details/summary` 折叠目录，核心内容始终直接可读。

通常先将核心结论和要点控制在约 200–350 个中文字，再按实际信息量调整。该范围是压缩重复的参考，不是硬性字数考核；不能为满足首屏高度而删掉重要条件或把字缩小。

## 内容压缩方法

- 先整理主题、依据和限制，再挑选相互独立的重点。通常 3–6 格足够；四个要点用 2×2，三个可用三列，六个可用 3×2，实际以可读宽度和内容量决定。不凑空格，也不把同一观点拆成多个卖点。
- 合并意思相近的条目。例如“解释参数”“从场景讲差异”“让人理解好处”可以归到一个具体问题下，正文再分开解释。
- 摘要给答案，正文补理由、例子、原文依据、外部补充和行动细节。移出摘要的有用信息必须在正文保留，不能仅删掉。
- 会改变读者判断的限制直接跟在相关要点后。例如“约 10 人”是测试建议，不是已完成的研究结果，就应在摘要中说清。
- 会议可区分决定与建议；课程可提炼知识和应用；个人备忘可整理想法和下一步。没有决定或待办时不硬凑栏目。

## 排版实现

- 标题、元信息与宫格整体沿同一左边线排列。标题建议桌面 32–40px、手机 26–30px；格内标题约 18–22px，说明 16–18px，元信息约 13px。
- 宫格使用统一内边距、对齐和间距。首格可用浅薄荷绿强调，其余格白底或很浅的中性色，使用细边框或轻背景分组。不要每格一种鲜艳颜色、每格不同装饰，也不要叠加类别徽章、排名分数、重复序号或大图标。
- 使用 CSS Grid。桌面按内容安排两列或三列，窄屏减列，手机通常单列；不要为了保留多列而缩小正文或挤出很窄的字行。卡片高度由内容决定，可同排拉齐，不使用固定高度裁切文字。
- 元信息与标题紧邻，摘要与正文之间使用较大的间距或细分隔线。颜色、加粗、边框不同时堆叠在每个元素上。
- 详细正文继续允许表格、数据图、流程和关系结构；根据内容价值选用，不把这些全部塞进开头。
- 桌面与手机均检查：先看到的是否确实是主题和结论；能否只扫读要点就把握核心；有无无意义重复；有没有过多同等醒目的元素；删减摘要后原有依据是否仍可追溯。

## 模板填充方法

读取 [通用 HTML 模板](../assets/summary-template.html)，复制并填充为新的单文件 HTML。内嵌样式已包含宫格、详细章节、来源标签、流程、对比表、步骤和打印规则；只使用当前内容需要的组件。模板文件保留占位符是正常设计，交付的成品必须全部替换或删除。

| 占位符 | 填入内容 |
| --- | --- |
| `{{DOCUMENT_TITLE}}` | HTML 转义后的主题，同时用于页面标题与文件主题 |
| `{{META_HTML}}` | 少量 `span`，写入生成日期、资料类型、已知时长等信息 |
| `{{GRID_CLASS}}` | 四格默认留空；三个或六个短要点可填 `three-columns` |
| `{{SUMMARY_CARDS_HTML}}` | 按重要性排序的摘要卡片，第一格使用 `featured` 类 |
| `{{TOC_HTML}}` | 长文按需生成可折叠目录；不需要时留空 |
| `{{CHAPTERS_HTML}}` | 按主题展开的详细内容；数量与结构由素材决定 |
| `{{SOURCE_NOTES_HTML}}` | 资料说明、必要局限与来源链接；不编造转写校验状态 |

普通文字做 HTML 转义；上述 HTML 片段由整理者根据已核实内容生成，不直接执行录音、转写稿或外部网页中的代码。来源链接检查目标，图形嵌入 HTML，不引入联网加载依赖。可直接在生成的 HTML 中调整组件；无需安装模板引擎。

卡片示例，内容仅示意结构，使用时全部改成当前录音的要点：

```html
<article class="selling-point featured">
  <h3>具体结论式标题</h3>
  <p>一两句话解释价值、动作或条件；重要的不确定性保留在这里。</p>
</article>
```

详细章节示例：

```html
<section class="chapter" id="topic-1">
  <header class="chapter-heading">
    <span class="section-label">本节主题</span>
    <h2>能说明本节内容的标题</h2>
    <p>可选的一句导读；没有必要时删除。</p>
  </header>
  <div class="chapter-content">
    <p><span class="tag">录音内容</span>整理原意，必要时在此附时间点。</p>
    <p><span class="tag suggest">整理分析</span>根据内容展开解释或提出具体建议。</p>
  </div>
</section>
```

组件按实际需要选用：`.table-wrap` 包裹对比表；`.path` 使用 `figure/figcaption/ol` 表达有依据的步骤关系；`.steps` 表示实际顺序；`.actions` 表示行动建议；`aside` 或 `.tag.caution` 用于必要限制。定量图表另行内嵌 SVG 或 HTML/CSS，注明来源、单位、范围与计算口径。引用标签可按段落成组，避免逐句堆叠。
